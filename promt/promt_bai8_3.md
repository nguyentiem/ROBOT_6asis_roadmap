CẦN NẮM ĐƯỢC (mục tiêu bài học):
- MoveIt 2 là gì: khung phần mềm lập kế hoạch chuyển động cho cánh tay robot trên ROS 2: IK, lập kế hoạch tránh va chạm, thực thi, planning scene, thị giác, gắp thả; ghép các bài 3, 5, 6.4 thành một hệ thống hoàn chỉnh
- Kiến trúc: move_group node (trung tâm) nhận yêu cầu → planning pipeline (OMPL, Pilz, CHOMP, STOMP) → planning scene (robot + vật cản + octomap) → quỹ đạo → ros2_control (FollowJointTrajectory, bài 8.2); các giao diện: MoveGroup action, MoveItPy (Python), move_group_interface (C++), RViz MotionPlanning plugin, MoveIt Task Constructor (giới thiệu)
- Setup Assistant (moveit_setup_assistant): nạp URDF/xacro → tự va chạm (Self-Collisions: tạo ma trận SRDF bỏ qua cặp link liền kề/không bao giờ va chạm) → Planning Groups (ví dụ arm: chain base_link → tool0, kinematic solver; gripper) → Robot Poses (home, ready...) → End Effectors → Passive Joints → Controllers (ros2_control) → Perception (tùy) → Launch files → tạo package <robot>_moveit_config; file sinh ra: SRDF, kinematics.yaml, joint_limits.yaml, ompl_planning.yaml, moveit_controllers.yaml, launch/, config/
- Planning group: tập khớp được điều khiển cùng nhau; chain định nghĩa bằng khâu đầu và cuối; tip link; group state (tư thế đặt tên)
- Bộ giải IK (kinematics plugin): KDL (mặc định, IK số kiểu Jacobian, chậm hơn, có thể kẹt), TRAC-IK (kết hợp Newton và SQP, tỉ lệ thành công cao hơn), bio_ik (đa mục tiêu), IKFast (giải tích, nhanh, cần sinh code cho robot cụ thể, phù hợp robot 6 trục có cổ tay cầu, liên hệ bài 3.2); tham số kinematics.yaml: kinematics_solver, search_resolution, timeout, attempts; liên hệ bài 3.3–3.4
- Bộ lập kế hoạch: OMPL (RRT, RRTConnect — mặc định thường là RRTConnect, RRT*, PRM, BiTRRT...; liên hệ bài 6.4); lập kế hoạch trong không gian khớp, đích là pose (IK) hoặc cấu hình khớp; planning_time, num_planning_attempts, velocity/acceleration scaling; Pilz Industrial Motion Planner (PTP, LIN, CIRC — tương ứng MoveJ, MoveL, MoveC ở bài 5.2); đường đi cartesian (compute_cartesian_path / waypoints); time parameterization (TOTG — time-optimal trajectory generation, Ruckig...; bài 5.1, 5.3)
- Planning scene: robot state + vật va chạm (box, sphere, cylinder, mesh); thêm/xóa vật bằng PlanningSceneInterface/API apply_planning_scene; gắn vật vào gripper (attached collision object) để tránh va chạm khi cầm vật; allowed collision matrix (ACM) cho phép tiếp xúc (ví dụ gripper chạm vật khi gắp); octomap từ camera độ sâu (giới thiệu); kiểm tra trạng thái hợp lệ (state validity)
- Ràng buộc (constraints): ràng buộc vị trí/hướng (ví dụ giữ ly nước thẳng đứng), giới hạn khớp, ràng buộc đường đi (giới thiệu; OMPL chậm, cần tham số)
- Quy trình dùng: (1) Setup Assistant tạo moveit_config; (2) chạy demo.launch.py với mock hardware/RViz; (3) kéo marker trong RViz → Plan → Execute; (4) viết code Python/C++ đặt mục tiêu; (5) thêm planning scene; (6) (tùy chọn) Gazebo hoặc robot thật; liên hệ bài 6.3: pick-and-place
- Python: MoveItPy (moveit_py) trong ROS 2 mới, hoặc pymoveit2 (bên thứ ba); các thao tác: set_goal_state, plan(), execute(), planning_scene_monitor; chú ý API thay đổi theo phiên bản (kiểm tra tài liệu); thay thế: ros2 action MoveGroup gửi trực tiếp
- C++: MoveGroupInterface: setPoseTarget, setJointValueTarget, plan, execute, computeCartesianPath, attachObject
- Đánh giá và gỡ lỗi: plan thất bại (No IK solution, goal state in collision, timeout, start state out of bounds), cách đọc log, tăng planning_time, đổi planner, kiểm tra tự va chạm trong SRDF, giới hạn khớp, vật cản đè lên robot, đích ngoài tầm với
- MoveIt Servo (giới thiệu): điều khiển thời gian thực bằng vận tốc (liên hệ bài 4.3), MoveIt Task Constructor cho gắp thả nhiều bước (giới thiệu)

VÍ DỤ ROBOT: Panda (moveit_resources_panda_moveit_config và tutorial MoveIt) hoặc UR5 qua ur_moveit_config (gói Universal Robots, kiểm tra tên/launch theo phiên bản); tutorial chính thức của MoveIt 2 làm khung. Không bịa nội dung; ghi chú những chỗ phải kiểm tra tài liệu moveit.picknik.ai và ros2 pkg list.

VÌ SAO CẦN HỌC: MoveIt là công cụ phổ biến nhất để cho robot cánh tay ROS đi tránh vật cản và gắp thả; nó gom FK, IK, Jacobian, quỹ đạo, tránh va chạm vào một gói, nên hiểu những bài trước giúp bạn đọc hiểu log và chỉnh tham số khi nó thất bại.

LƯU Ý KỸ THUẬT: HTML không chạy MoveIt; mô phỏng hiệu ứng bằng JavaScript: sơ đồ kiến trúc SVG; Setup Assistant giả lập (các tab có form); RViz MotionPlanning thu nhỏ với robot phẳng 2-3 khâu hoặc UR5/Panda giả 3D (Canvas hoặc three.js r128 từ cdnjs; tự viết điều khiển xoay góc nhìn, không dùng OrbitControls có sẵn, không dùng CapsuleGeometry); RRT-Connect, kiểm tra va chạm, IK tự viết bằng JS ở bản đơn giản (dùng lại ý tưởng bài 6.4 và 3.3); log lỗi mẫu. Nhấn mạnh: kết quả mô phỏng chỉ minh họa, người học chạy MoveIt thật.

MINH HỌA TƯƠNG TÁC BẮT BUỘC:
a) Kiến trúc MoveIt: sơ đồ khối (RViz/Python/C++ → move_group → planning pipeline → planning scene → controller → robot); animation một yêu cầu "tới tư thế này" đi qua các khối; bấm khối để xem mô tả, topic/action tương ứng (MoveGroup action, /joint_states, /tf, FollowJointTrajectory).
b) Setup Assistant giả lập: các tab (Start, Self-Collisions, Virtual Joints, Planning Groups, Robot Poses, End Effectors, Controllers, Launch Files, Generate); mỗi tab có form nhỏ và hướng dẫn; checklist tick; ở Self-Collisions hiển thị ma trận cặp link (tô màu: liền kề, luôn va chạm, không bao giờ va chạm) và giải thích vì sao tạo ma trận này giúp planner nhanh hơn; ở Planning Groups chọn chuỗi base_link → tool0 và solver.
c) Cấu trúc package sinh ra: cây thư mục <robot>_moveit_config (config/{srdf, kinematics.yaml, joint_limits.yaml, ompl_planning.yaml, moveit_controllers.yaml}, launch/); bấm file thì hiện nội dung mẫu và chú thích từng dòng; sửa tham số (ví dụ kinematics_solver, planning time) và hiện tác động bằng chữ.
d) RViz MotionPlanning: robot, marker tương tác để kéo đích; nút Plan, Execute, Plan & Execute; hiển thị quỹ đạo dạng "bóng" robot nhiều khung (trail), thanh trượt quỹ đạo; panel Planning (planner, planning time, attempts, velocity scaling); chọn start/goal state; trạng thái hợp lệ (xanh) / va chạm (đỏ).
e) So sánh bộ giải IK: cùng một đích, ba bộ giải giả lập (KDL, TRAC-IK, IKFast) với thời gian, tỉ lệ thành công, số nghiệm (số liệu mô phỏng minh họa, ghi chú không phải đo thật); thanh trượt timeout; tình huống gần singularity/giới hạn khớp thì KDL thất bại; bảng khi nào chọn gì (liên hệ bài 3.2, 3.3).
f) OMPL planner: robot phẳng nhiều khâu hoặc C-space 2D (như bài 6.4); chọn planner (RRT, RRTConnect, RRT*, PRM, BiTRRT); chạy cùng bài toán; hiển thị thời gian, độ dài đường, số nút; slider planning_time; nút "chạy 20 lần" thống kê; ghi chú RRTConnect mặc định nhanh nhưng không tối ưu.
g) Pilz PTP/LIN/CIRC: ba nút trên robot phẳng; vết đầu công cụ cong/thẳng/tròn; bảng tương ứng MoveJ/MoveL/MoveC (bài 5.2); LIN có thể thất bại khi qua gần singularity (cảnh báo).
h) Planning scene: thêm vật cản (hộp, trụ, cầu) bằng nút và kéo thả; robot lập kế hoạch lại tránh vật; "gắn vật" vào gripper thì vật di chuyển theo và robot tránh va chạm cả vật đang cầm; ma trận ACM bật/tắt cho phép gripper chạm vật; octomap giả lập (các voxel) từ camera độ sâu.
i) Time parameterization: quỹ đạo đường đi (chỉ hình học) → gán thời gian với velocity/acceleration scaling (slider 0.1–1.0); đồ thị q̇(t), q̈(t) và giới hạn; thấy chậm lại khi giảm scaling (bài 5.1/5.3).
j) Ràng buộc đường đi: ví dụ giữ hướng công cụ thẳng đứng trong lúc di chuyển (cầm ly); so sánh có và không ràng buộc (ly nghiêng/không nghiêng) và thời gian lập kế hoạch tăng (hiển thị mô phỏng); giải thích vì sao khó.
k) Đọc log và sửa lỗi: bảng log mẫu (No IK solution, Goal state in collision, Timeout, Start state out of bounds, Controller failed...); với mỗi dòng người học chọn nguyên nhân và cách sửa trong danh sách; phản hồi đúng/sai; kèm checklist debug (tăng planning_time, đổi planner, thêm ACM, kiểm tra SRDF/giới hạn khớp).
l) Quy trình gắp thả: sơ đồ các giai đoạn (pre-grasp → grasp → gắn vật → lift → place → release) tương ứng bài 6.3; mỗi giai đoạn ghi lệnh MoveIt tương ứng (plan tới pose, compute_cartesian_path, attach/detach object, ACM); animation robot 2D chạy chu trình với vật cản.
m) Servo và Task Constructor (giới thiệu): hai thẻ với sơ đồ ngắn; khi nào dùng (điều khiển bằng tay cầu/vận tốc so với tác vụ nhiều bước).
n) UR5/Panda giả 3D (nếu đủ chỗ): robot với hộp cản; nút "Plan" chạy RRT-Connect đơn giản với kiểm tra va chạm bằng cầu bao; hiển thị đường đi vòng; hoặc animation dữ liệu tính trước.

VÍ DỤ CÓ LỜI GIẢI: (1) chạy demo MoveIt của Panda hoặc UR5 (ghi lệnh theo tài liệu chính thức MoveIt 2 cho phiên bản đang dùng, nhắc kiểm tra), kéo marker và Plan & Execute; kết quả mong đợi; (2) đọc kinematics.yaml, giải thích từng tham số (kinematics_solver, kinematics_solver_search_resolution, kinematics_solver_timeout) và cách đổi sang TRAC-IK (cần cài package, kiểm tra tên); (3) viết chương trình Python đặt mục tiêu pose, plan và execute bằng MoveItPy hoặc pymoveit2 (ghi rõ phụ thuộc phiên bản); (4) thêm hộp cản vào planning scene bằng Python rồi lập kế hoạch tránh; (5) compute_cartesian_path đi đường thẳng 10 cm xuống rồi lên (tỉ lệ fraction và cách kiểm tra).

CODE MẪU (thật, ghi rõ phiên bản, chỗ nào API thay đổi phải ghi chú): lệnh chạy demo (ros2 launch <moveit_config> demo.launch.py — kiểm tra tên), lệnh Setup Assistant (ros2 launch moveit_setup_assistant setup_assistant.launch.py); đoạn YAML kinematics.yaml, ompl_planning.yaml, joint_limits.yaml (mẫu, giải thích từng khóa); node Python bằng MoveItPy (khởi tạo, get_planning_component, set_goal_state(pose_stamped_msg=..., pose_link=...) hoặc robot_state, plan(), execute(robot_trajectory, controllers=[])), kèm cảnh báo API đổi theo phiên bản; (nếu muốn) pymoveit2 như lựa chọn phổ biến; C++ MoveGroupInterface ngắn (setPoseTarget, plan, execute, computeCartesianPath, attachObject); thêm CollisionObject (box) vào PlanningScene: tạo moveit_msgs/CollisionObject, SolidPrimitive, publish hoặc apply_planning_scene; attached object; ACM; (tùy chọn) MoveIt Servo ở mức khái niệm; mẹo gỡ lỗi (ros2 topic echo /joint_states, ros2 control list_controllers, rqt_graph, log level). Không bịa tên package/tham số; ghi "kiểm tra bằng ros2 pkg list và tài liệu moveit.picknik.ai".

LỖI THƯỜNG GẶP: SRDF thiếu hoặc Self-Collisions chưa tạo (planner báo va chạm giả), planning group sai chuỗi khớp, đích ngoài tầm với (No IK solution), đích hoặc điểm đầu nằm trong va chạm, vật cản đè lên robot, KDL timeout khi gần singularity/giới hạn khớp, planning_time quá ngắn, đổi planner nhưng chưa tải cấu hình, quên velocity/acceleration scaling dẫn tới chạy quá nhanh, controller chưa active hoặc tên khớp lệch (execute thất bại), quên gắn vật vào gripper nên robot đâm vật đang cầm, ACM sai (không cho gripper chạm vật khi gắp), dùng compute_cartesian_path mà không kiểm tra fraction, API MoveItPy/ros-planning đổi theo phiên bản (lấy ví dụ cũ), nhầm hệ tọa độ đích (frame_id), quaternion không chuẩn hóa, dùng Gazebo thời gian mô phỏng nhưng quên use_sim_time, chạy trên robot thật mà không giới hạn tốc độ.
